Chapter 1 of the DL Guide - Where each algorithm sits in the AI / ML / DL stack

The PDF (Ch 1, page 5) defines three nested circles:

  • AI - any technique that lets computers mimic intelligence (Netflix recommendations, AlphaGo).
  • ML - systems that learn from data without explicit programming. Examples: Linear Regression, Random Forest, SVM, Naive Bayes.
  • DL - subset of ML that uses deep neural networks to automatically extract features. Examples: CNN, RNN/LSTM, Transformer, GAN.
Dimension Classical ML Deep Learning
Feature engineering Manual - domain experts hand-craft features Automatic - learns features from raw data
Data requirements Works with smaller datasets Needs large datasets for optimal performance
Best data type Structured / tabular Unstructured (image, text, audio)

Where each algorithm in this notebook sits:

Algorithm Family Why we picked it
Logistic Regression Classical ML Interpretable linear baseline (W01-W02)
KNN Classical ML Instance-based, distance-driven (W03)
Naive Bayes Classical ML Probabilistic, assumes independence (W03)
Decision Tree Classical ML Rule-based, no scaling required (W03)
SVM Classical ML Maximum-margin, kernel trick (W03)

Why this matters for heart.csv: with only ~300 unique rows of structured tabular data, the PDF's Ch 1 rule says classical ML is preferred. We expect Random Forest / Gradient Boosting to beat the MLP. The MLP is included to demonstrate the DL paradigm, not to win.

In [10]
results = {}

def evaluate(name, model, Xtr, ytr, Xte, yte, store=True):
    model.fit(Xtr, ytr)
    yhat = model.predict(Xte)
    # probabilities for ROC-AUC (fall back to decision_function for SVM without prob)
    if hasattr(model, 'predict_proba'):
        yprob = model.predict_proba(Xte)[:, 1]
    elif hasattr(model, 'decision_function'):
        yprob = model.decision_function(Xte)
    else:
        yprob = yhat
    acc = accuracy_score(yte, yhat)
    pre = precision_score(yte, yhat)
    rec = recall_score(yte, yhat)
    f1  = f1_score(yte, yhat)
    auc = roc_auc_score(yte, yprob)
    if store:
        results[name] = {
            'Accuracy': acc, 'Precision': pre, 'Recall': rec,
            'F1': f1, 'ROC_AUC': auc,
            'model': model, 'y_pred': yhat, 'y_prob': yprob
        }
    print(f'{name:30s} acc={acc:.3f}  prec={pre:.3f}  rec={rec:.3f}  F1={f1:.3f}  AUC={auc:.3f}')
    return model

4.7 Neural Network / MLP (W05-W06)

Chapter 2 of the DL Guide - How a neural network learns

A neural network is built from three components (Ch 2 page 9):

  • Weights w - each connection between neurons has a weight that amplifies or diminishes the signal. Learned during training.
  • Bias b - added to the weighted sum, allows the activation function to shift. Learned.
  • Depth - multiple hidden layers enable hierarchical feature learning (broader -> more granular patterns).

Each neuron computes:

$$z = w_1 x_1 + w_2 x_2 + \dots + w_n x_n + b, \qquad a = f(z)$$

where f is a non-linear activation function. Without f the whole network would collapse into a single linear transformation.

Activation Range Where used
ReLU max(0, x) [0, +inf) Hidden layers (default in our MLP)
Sigmoid (0, 1) Binary output (and inside LogReg)
Softmax (0, 1), sums to 1 Multi-class output

The training cycle (Ch 2 page 8) repeats four steps until the loss converges:

  1. Forward pass - input flows through layers to produce a prediction.
  2. Loss calculation - compare prediction to target (binary cross-entropy here).
  3. Backpropagation - the chain rule decomposes dL/dw through each layer.
  4. Weight update - w_new = w_old - lr * dL/dw. We use Adam (Ch 2 page 13): adaptive learning rate per parameter, combining momentum and RMSprop.

Chapter 3 of the DL Guide - The FNN architecture

A Multi-Layer Perceptron is a Feedforward Neural Network (FNN). Information moves in one direction only - input -> hidden layers -> output. No cycles, no recurrence.

Architecture decisions (Ch 3 page 15):

  • Depth - number of hidden layers. More layers = more complex patterns, but harder to train.
  • Width - neurons per layer. More neurons = more capacity, but more parameters to overfit.
  • Activation - ReLU recommended for hidden layers.
  • Initialization - Xavier/Glorot or He initialization. Sklearn handles this automatically.
  • Output - Sigmoid for binary classification.

For our heart.csv we use two hidden layers (64, 32 neurons) with ReLU, trained by Adam. This is the simplest deep model we can build on tabular data.

The PDF (Ch 1) explicitly notes: FNN/ANN is the right architecture for tabular data. For images use CNN, for sequences use RNN/LSTM. The full Keras / TensorFlow CNN-RNN-LSTM comparison lives in compare-between-dl-models.ipynb in W05-W06.

4.9 Keras CNN / SimpleRNN / LSTM on tabular data (W05-W06 - adapted)

These three architectures were built for sequences (text, audio, time-series) or spatial grids (images). heart.csv is neither - it is 13 independent tabular features per patient. Still, we can force them onto this dataset to demonstrate the architecture (PDF Ch 4, 5, 6) by treating each row as a length-13 "sequence" with 1 channel.

Architecture What it does on tabular data
1D CNN Learns small filters that fire on local combinations of adjacent features. The "adjacency" here is arbitrary - it depends on column order.
SimpleRNN Walks across the 13 features one at a time, carrying a hidden state. Vanishing gradient is not an issue at length 13.
LSTM Same walk, but with gated cell state. Overkill at length 13 but matches the PDF Ch 6 architecture.

Honest expectation: these models will underperform the trees because the "sequence" structure is fake. Their job here is pedagogical - showing that you can build them with Keras and that they run on the same dataset. The real wins for these architectures are on text (IMDB - see compare-between-dl-models.ipynb), not on 13-feature medical records.

Requires TensorFlow / Keras. If you do not have it, skip this cell - the rest of the notebook still works.

import tensorflow as tf
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import (
    Conv1D, GlobalMaxPooling1D, SimpleRNN, LSTM, Dense, Dropout, Input
)

tf.random.set_seed(RANDOM_STATE)

# Reshape (n_samples, 13) -> (n_samples, 13, 1) so Conv1D/RNN/LSTM see a "sequence".
X_train_seq = X_train_s.reshape(-1, X_train_s.shape[1], 1).astype('float32')
X_test_seq  = X_test_s.reshape(-1,  X_test_s.shape[1],  1).astype('float32')
n_features  = X_train_s.shape[1]


def build_cnn():
    return Sequential([
        Input(shape=(n_features, 1)),
        Conv1D(32, kernel_size=3, activation='relu', padding='same'),
        GlobalMaxPooling1D(),
        Dropout(0.3),
        Dense(16, activation='relu'),
        Dense(1, activation='sigmoid'),
    ])


def build_rnn():
    return Sequential([
        Input(shape=(n_features, 1)),
        SimpleRNN(32),
        Dropout(0.3),
        Dense(1, activation='sigmoid'),
    ])


def build_lstm():
    return Sequential([
        Input(shape=(n_features, 1)),
        LSTM(32),
        Dropout(0.3),
        Dense(1, activation='sigmoid'),
    ])


def evaluate_keras(name, model, epochs=60, batch_size=16):
    model.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])
    model.fit(X_train_seq, y_train,
              epochs=epochs, batch_size=batch_size,
              validation_split=0.1, verbose=0)
    yprob = model.predict(X_test_seq, verbose=0).ravel()
    yhat  = (yprob > 0.5).astype('int32')
    acc = accuracy_score(y_test, yhat)
    pre = precision_score(y_test, yhat)
    rec = recall_score(y_test, yhat)
    f1  = f1_score(y_test, yhat)
    auc = roc_auc_score(y_test, yprob)
    results[name] = {
        'Accuracy': acc, 'Precision': pre, 'Recall': rec,
        'F1': f1, 'ROC_AUC': auc,
        'model': model, 'y_pred': yhat, 'y_prob': yprob,
    }
    print(f'{name:34s} acc={acc:.3f}  prec={pre:.3f}  rec={rec:.3f}  F1={f1:.3f}  AUC={auc:.3f}')

5. Hyperparameter tuning (GridSearchCV)

Chapter 3 of the DL Guide - Hyperparameter tuning strategies

The PDF (Ch 3 page 16, repeated in Ch 11 page 49) lists three approaches and the key hyperparameters to tune. They apply to any ML model, not just neural networks.

Method How it works Trade-off
Grid Search Exhaustively try all combinations Thorough but computationally expensive
Random Search Sample random combinations Often finds good solutions faster than grid search
Bayesian Optimization Use past evaluation results to build a probabilistic model that picks the next parameters intelligently Most efficient, more complex to set up

Key hyperparameters named in the PDF for each model family:

  • Trees (RF, GB, DT): number of trees, max depth, min samples per leaf, min samples per split.
  • KNN: number of neighbors, weight function, distance metric (p=1 Manhattan, p=2 Euclidean).
  • SVM: regularization C, kernel type, gamma (RBF spread).
  • Neural nets: learning rate, batch size, layer count, neurons per layer, dropout rate, activation.

Below we apply Grid Search to the three strongest model families - KNN, SVM, Random Forest - using 5-fold Stratified CV with F1 as the scoring metric. CV stops us from tuning on the test set, which would be data leakage.

6. Hybrid (ensemble) approaches

Three styles:

  1. Soft Voting - average the predicted probabilities of several diverse models.
  2. Hard Voting - majority vote of class predictions.
  3. Stacking - feed base-model predictions into a meta-learner (Logistic Regression).

8. Discussion and conclusion

What we expect to see on this dataset:

  • Naive Bayes is fast but its independence assumption hurts on correlated medical features.
  • Logistic Regression is a strong, interpretable baseline.
  • KNN and SVM benefit a lot from scaling and hyperparameter tuning.
  • Decision Tree overfits unless pruned (no scaling needed).
  • Random Forest and Gradient Boosting usually top the leaderboard on small tabular data.
  • The MLP can match the trees, but on ~300 unique rows it does not have enough data to clearly win.
  • The K-Means hybrid sometimes lifts the linear model because cluster IDs encode non-linear structure that Logistic Regression cannot learn by itself.
  • Voting and Stacking usually beat any single model by combining complementary errors.

Take-aways for the course:

  1. Always check for duplicates before splitting; ~70% of heart.csv rows are duplicated.
  2. Scaling is required for KNN, SVM, MLP, and Logistic Regression.
  3. Use GridSearchCV with stratified CV - never tune on the test set.
  4. Hybrid models (Voting, Stacking, KMeans-augmented features) are easy wins once you have several base learners.
  5. Pick the metric that matches the cost of mistakes - in medical screening, recall of the positive class is often more important than raw accuracy.

Chapter 1 of the DL Guide - When to use ML vs DL (revisited)

"Use DL for large volumes of unstructured data (images, text, audio) where automatic feature extraction provides significant advantage. Use ML for structured/tabular data with limited samples." - PDF Ch 1 page 6

That quote explains the results above:

  • heart.csv is structured + small -> classical ML wins, ensembles dominate.
  • If we had 100k chest X-ray images we would replace this pipeline with a CNN (PDF Ch 4).
  • If we had time-series ECG signals we would use LSTM (PDF Ch 6).
  • If we had clinical notes we would use a Transformer (PDF Ch 8).

Classical ML beats deep learning on small tabular data

The PDF (Ch 1, page 6) predicted this and the run confirmed it:

  • All four DL-derived models (MLP, SimpleRNN, LSTM, CNN) live in the bottom half of the leaderboard.
  • CNN 1D is dead last at F1 = 0.536. The convolution treats adjacent columns as locally related - but the 13 features here have no spatial meaning. The "fake sequence" hypothesis breaks the model.
  • SimpleRNN and LSTM land at F1 ~ 0.75, on par with the MLP. RNNs walking 13 independent features behave like a small FNN with hidden state - no harm, no real win.

Wins for classical ML

  • SVM (tuned) edged out everyone (F1 0.829, AUC 0.865).
  • K-Means hybrid tied with Logistic Regression to 4 decimals (F1 0.8235, AUC 0.8712). The cluster ID feature added zero information for this split - the linear model already saw what K-Means saw.
  • Naive Bayes has the best AUC (0.884) despite mid-pack F1. It ranks risk probabilities best; lowering the decision threshold below 0.5 would raise its F1.

Surprises worth noting

  • Gradient Boosting baseline collapsed to F1 = 0.746 - well below Random Forest baseline at 0.800. Small-data tax: GB's sequential residual fitting overfits on 241 rows with default hyperparameters. A tuned GB (learning_rate=0.05, max_depth=3) would likely recover.
  • Random Forest baseline (0.800) beat Random Forest tuned (0.788). The grid search optimized for CV F1, but the chosen max_depth=5 hurt on the test set. Classic CV-vs-holdout noise on 61 test rows.
  • Voting (hard) beat Voting (soft). Soft averages probabilities - but the diverse base models disagree on calibration. Hard majority is more robust here.

TF warnings to ignore

The "tracing is expensive" warnings in the §4.9 cell are benign - Keras complains about retracing across the three sequential predict() calls. No effect on results.

General take-aways

  1. For binary classification on small tabular data, prefer SVM (tuned) or Logistic Regression - they are statistically tied at the top here.
  2. Use Naive Bayes when calibrated risk scores matter more than raw F1 - best AUC at 0.884.
  3. Deep learning is not the right tool for ~300-row tabular tasks. The CNN, RNN and LSTM are included for completeness, not for performance - they confirm the "DL needs big unstructured data" rule.
  4. Default ensemble hyperparameters are not safe on small data. The Gradient Boosting collapse and the RF-tuned regression both show that defaults and grid-search picks can lose to plain baselines.
